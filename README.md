# AWS 構成ドリフト自動検知・通知システム
AWS上のインフラ構築において、手動操作による「構成ドリフト（IaCコードと実際のリソース状態の乖離）」を即座に検知し、Slackへ自動通知するイベント駆動型のガバナンス監視システムです。

## 研究概要
本研究は、IaC（Infrastructure as Code）で管理されているAWS環境において、管理コンソール画面などから行われた「手動での設定変更（構成ドリフト）」を即座に検知し、Slackへ自動通知するシステムです。

Terraformを用いたインフラ管理において課題となる「コードと実際のリソース状態の乖離」を早期に発見し、セキュアで一貫性のあるインフラ運用を実現することを目的としています。

## 解決したい課題
* IaC管理外の予期せぬ手動変更（セキュリティグループの開放など）によるセキュリティリスクの防止
* 複数人開発における「誰が・いつ・何を変更したか」のブラックボックス化の解消
* `terraform plan` 実行時まで構成のズレに気づけないタイムラグの解消

## アーキテクチャ構成
AWSのサーバーレスアーキテクチャを活用し、スケーラブルかつ疎結合なイベント駆動型システムを構築しています。

<img width="10323" height="7446" alt="Image" src="https://github.com/user-attachments/assets/cb74f77f-9d94-4d16-a597-c2677bd63ba8" />

1. **AWS CloudTrail**: AWS環境内でのAPI操作（手動変更）を監視・記録
2. **Amazon EventBridge**: CloudTrailの記録から、特定のリソース変更（例：セキュリティグループのルール変更）イベントをフィルタリングして検知
3. **Amazon SNS**: EventBridgeからのアラートを受け取り、後続システムへルーティング（将来的な複数宛先への通知拡張を考慮）
4. **Amazon SQS**: SNSからのメッセージを一時的にキューイングし、Lambdaの実行失敗時の再送処理や、大量イベント発生時の負荷分散（バッファ）を担う
5. **AWS Lambda (Python 3.9)**: SQSからイベントを受け取り、メッセージを解析・整形してSlack APIへPOST送信
6. **AWS KMS**: Lambdaの環境変数（Slack Webhook URL）をセキュアに暗号化・復号
7. **Slack**: 開発・運用チームへのリアルタイムアラート通知

## 使用技術・ツール
* **インフラ構築**: Terraform
* **クラウドプロバイダ**: AWS (CloudTrail, EventBridge, SNS, SQS, Lambda, IAM, KMS)
* **プログラミング言語**: Python 3.9 (Lambda関数用)
* **通知**: Slack Webhook API
